# 潜江干瞪眼管理后台

线上入口：[https://gmhiu.com/admin](https://gmhiu.com/admin)。后台使用独立管理员密码；密码仅以加盐 scrypt 哈希保存在服务器 /var/lib/qjqp/admin-password.json，不放进 Git、安装包或浏览器存储。登录会话为 8 小时，保存在服务器内存中；服务重启后需要重新登录。浏览器仅接收 HttpOnly、SameSite=Strict、Secure 会话 Cookie，修改操作另需 CSRF 令牌。密码错误会限速。可在「备份与系统」页面修改密码，修改后全部会话立即失效。

后台目前有十四个入口：

| 入口 | 能做什么 |
| --- | --- |
| 数据面板 | 玩家总数、在线人数、活跃房间、俱乐部、玩家与俱乐部房卡余额、归档牌局及最近七天趋势 |
| 玩家管理 | 按 ID/昵称搜索，查看房卡、房间、俱乐部与脱敏实名状态；调整房卡、停用/恢复账号 |
| 房间管理 | 查看当前房间状态、座位、机器人、托管和配置；开局后实时查看剩余牌堆并为指定玩家设置后续摸牌顺序；管理员可解散异常房间 |
| 牌局管理 | 按房号、战绩 ID 或玩家 ID 查归档战绩、每局积分与回放编号 |
| 俱乐部管理 | 查看部长、成员、玩法、房间及俱乐部房卡；调整俱乐部房卡、设置公告及关闭状态 |
| 房卡与奖励 | 设置首次加入俱乐部给俱乐部赠卡数量（默认 200），以及绑定邀请码时双方各得卡数量（默认 1000） |
| 机器人管理 | 开启或关闭机器人自动补位，查看当前机器人数量及所在房间 |
| 托管白名单 | 按玩家 ID 增删后台托管白名单，查看玩家当前是否正在托管 |
| 合伙人申请 | 查询玩家提交的合伙人联系信息 |
| 通知管理 | 向全部玩家或指定玩家发布文字通知，设有效期、撤回通知 |
| 大厅公告 | 设置大厅滚动公告、客服微信与 QQ；在线玩家立即刷新 |
| 热更新灰度 | 查看客户端版本上报，配置灰度范围并将候选版提升为稳定版 |
| 操作日志 | 审计登录、房卡调整、房间解散、账号状态、通知和设置变更 |
| 备份与系统 | 生成 SQLite 在线备份、查看存档信息、修改管理员密码 |

俱乐部房间只在首次开局时从俱乐部余额扣整桌费用，普通房仍按房主支付或 AA 从玩家余额扣费；建房和入座均不实际扣卡。入会奖励只在玩家首次加入同一俱乐部时发放，退出后再加入不重复领取；老成员不补发历史奖励。奖励设置只影响之后的入会或绑定邀请码。房卡调整要求填写原因，不能扣成负数。停用仍在房间里的玩家会被拒绝，须先处理房间；解散已开局房间会生成总结算，玩家停留在结算画面，自行返回大厅。俱乐部有人在房间时不能直接关闭。所有操作均由服务端校验。

房间详情在牌局进行中每 2.5 秒刷新剩余牌堆，使用工程原有的麻将牌面图显示实际摸牌顺序及各牌剩余数量。管理员选择目标玩家后，点击麻将牌就立即加入本局指定牌序；前移、后移、删除或清空也立即生效，不需要再点应用。服务端会预留这些牌，其他玩家摸牌时从未预留的牌中取牌。指定牌只影响本局，完成后自动清除；途中可以手动取消或重新设置。牌序与牌墙一起保存在运行快照中，服务重启后继续生效。若剩余牌全部被预留而另一位玩家仍需摸牌，牌序会终止以保证牌局正常推进。每次修改均记入后台操作日志。

机器人开关持久保存在 SQLite 中。开启后，服务端只会为用户 ID `285636` 创建、且符合补位条件的等待房间补充机器人；其他用户创建的房间不安排机器人。关闭后不再补充新机器人，等待中的机器人立即离开，正在打牌的机器人在当前小局结束后离开，不会中途破坏牌局。开关变化记录在后台操作日志。

托管白名单也持久保存在 SQLite 中。白名单玩家只在干瞪眼小局正在进行时由服务端强制托管，等待开局、局间结算和其他玩法均不生效。托管期间玩家仍是真人身份并正常计分，系统复用当前机器人策略自动出牌、碰、杠、胡和过。管理员加入或移出白名单会立即同步到正在进行的干瞪眼牌局，小局结束后自动解除后台托管；所有变更都记入操作日志。

机器人或后台托管玩家进入操作窗口时，服务端会立即发起 Jev 决策，同时为该次操作随机生成 `0.8–1.5` 秒的表现时间。Jev 提前返回时会等到随机时间到期再落子；届时仍未返回则立即使用本地机器人策略，迟到的结果作废，因此总出牌等待不超过 `1.5` 秒。

本地机器人会对最优候选执行两步摸打搜索，结合胡牌概率、预期得分、杠分、喜钱、癞子倍数和牌墙长度评估选择。对手模型只使用弃牌、副露、暗手张数等公开信息估计活张，不读取对手手牌或牌墙顺序。Jev 只在本地算法筛出的最多四个最优合法候选中做最终选择。潜江麻将机器人不评估、不奖励、不申报清一色或七小对路线。

「房卡与奖励」可设置新注册用户初始房卡，默认为 200 张。设置只影响之后新建的账号，不会追溯增减已有玩家的房卡。

游戏运行快照仍仅保留最近 300 场；后台另建牌局归档表，上线时回填快照里现存的最多 300 场，以后每场结算持续保存。已被旧策略删除的更早战绩无法恢复。归档保留结算与每局积分、回放编号，回放原始数据仍遵循游戏运行快照的保留策略。旧玩家没有注册时间，新玩家注册趋势从本功能上线后开始计算。审计日志与牌局归档分开存储，不会随快照重写而丢失；备份生成在 /var/lib/qjqp/backups/。

首次设置或紧急重置管理员密码，可在服务器上执行：

~~~bash
node /opt/qjqp/tools/admin-set-password.js /var/lib/qjqp/admin-password.json < /安全路径/密码文件
chown qjqp:qjqp /var/lib/qjqp/admin-password.json
systemctl restart qjqp
~~~

脚本从标准输入读取密码，命令行和 Git 中不保存密码原文。初始密码至少 12 个字符。管理员密码与此前运营消息的 SSH 密钥相互独立。
