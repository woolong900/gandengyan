# 修复边界与原厂 R234 一致性复核

复核对象是当前默认发布路径：原厂 Android R234 APK 作基包，iOS 用原厂 iOS 原生壳和已核对清单的 R234 跨平台资源。查看 `server/`、`tools/patchapk.js`、`tools/build-ios-ipa.js`、`tools/ios-sync-patches.js` 与已提交的修复记录。旧恢复的 Cocos 工程和 `--cocos-base ios` 的 R189/108 内置资源是对照路径，不能拿其补丁数量代表当前发布包。

## 能由服务端处理的既有问题

| 问题 | 当前责任位置 | 复核结果 |
| --- | --- | --- |
| 房间“不托管”仍被自动托管，取消后旧计时器再开启 | `server/rules.js`、`server/table.js`；`tools/test-trustee.js` | 超时配置、离线与托管状态、取消后的旧计时器全在服务端；无需 Cocos 补丁。 |
| 陪玩不进房、不出牌、牌墙空时永久等待 | `server/app.js`、`server/table.js`、`server/round.js` | 自动补座、重新计时和出牌选择均由服务端承担；旧提前触发的定时器已重排。 |
| 朝天与碰同时出现，朝天后错误补牌、卡住出牌 | `server/round.js` | 仅下发朝天候选、去掉普通碰、三张暗朝天或接别人打出的两张朝天不补牌，立即保持本人出牌权。**但客户端本地还要正确删手牌**，见下表。 |
| 朝天已杠出仍算双大胡，杠癞子/暗杠/热铳积分错算 | `server/round.js`、`server/rules.js` | 胡型和杠款按服务端牌面及规则计算，不靠客户端修改积分公式。 |
| 普通热铳与抢杠误播屁胡 | `server/round.js` | 普通热铳只发 32 位，普通抢杠只发 16 位；原厂客户端可播专用语音。带双大胡等复合位时仍需客户端胡型优先级，见下表。 |
| 游客同设备复用账号、实名校验、房卡与邀请奖励、战绩存储与权限 | `server/app.js`、`server/identity.js`、`server/records.js`、`server/store.js` | 账号归属、验证、奖励、SQLite 存储和访问权限在服务端；客户端仍必须提供稳定的设备标识并显示相关页面。 |
| 已废弃语音房拒建、语音上传限额和聊天频率限制 | `server/rules.js`、`server/voice.js`、`server/table.js` | 服务端阻止旧包开语音房，并约束体积、频率、访问权限；页面隐藏该选项是客户端用户体验要求。 |
| 发送语音者听到自己的录音 | `server/table.js:pushChat`；`tools/test-watch.js` | type=3 的语音只广播给其他成员，发送方仍收到成功回包。Android 重复的 `fromUid` 播放判断已移除；iOS 默认 R234 包跟随 Android 同一资源。 |

## 不能安全地只靠服务端处理的既有问题

| 问题 | 保留的客户端职责 | 为什么服务端不能替代 |
| --- | --- | --- |
| 朝天后的手牌显示和操作卡死 | Android `tools/patchapk.js` 的三张/两张手牌移除；旧 iOS 基线 `tools/ios-sync-patches.js` 的对应补丁 | `game_gang` 原厂会按普通杠从本地手牌移除四张/三张；服务端虽正确只扣三张/两张，客户端仍会先把本地牌删错。发重连快照不能保证本机首帧与操作恢复。 |
| 抢杠/热铳叠加双大胡的专用语音与动画 | 两端当前 R234 的 `_huSound`、`_huAnimationName` 优先检查 16/32 | 赢家确实可能持有三个朝天并抢杠，胡型需同时报 8 与 16；原厂按权重/位顺序先命中双大胡。服务端不能在保留完整胡型展示与杠分的同时，仅用一个 16 位表达两个胡型。 |
| 游客设备 ID 与登录页偶发一直加载 | Android 原生 ID 桥和游客登录请求；iOS 原生设备 ID 桥；`on_off_ok` 的启动兜底 | 服务端只能复用请求中带来的 ID，不能从共同公网 IP 推导物理设备；启动事件丢失发生在首次请求前。 |
| 创建房间右侧一瞬间空白、列表无限回弹和俱乐部背景露出大厅 | CheckType 首帧立即绘制、ScrollView 边界/内容尺寸及页面安全区 | 节点创建和布局在网络请求前或客户端本地执行；调整服务端回包不能改变首帧或滚动边界。 |
| iOS 创建俱乐部成功仍停在创建页、俱乐部空桌残影/方案切换后列表未更新 | 创建成功后的场景跳转、俱乐部数据刷新和 UI 事件通知 | 服务端已回正确俱乐部 ID 与最新房间列表，但原厂 UI 不执行对应跳转/重绘；单独推一条新消息也没有原厂监听逻辑。 |
| 旧 iOS 内置版分数放大十倍 | **仅** `--cocos-base ios` 对照构建里的旧资源除法；当前默认 R234 构建不执行 | 实时 JSON 与历史 protobuf 分数字段按整数协议存放十分之一分，2.5 分档不能统一下发小数；若全局缩小，Android 与历史数据都受影响。当前 R234 已原生读取 `score_ratio`，见下方核对。 |
| 实名填写空格或小写 x 后，首次成功页显示错误 | 客户端提交前规范姓名/身份证和已脱敏值的显示兼容 | 服务端会校验并保存规范值，但成功后原厂页面立即读取刚输入的本地字符串；若本地未处理，姓名前导空格会令页面首字为空。 |
| 微信登录/分享回调、语音原生桥、iOS 首屏停住或闪退 | 自己的 AppID、Universal Link/签名、原生 SDK 与 iOS 桥接 | 这些故障发生在系统 SDK 或客户端启动，服务端尚未收到请求；登录和分享对应的服务端鉴权/落地页仍保留。 |
| iOS/Android 牌桌灯盘、背景、人物、比例及所有品牌/玩法按钮 | Cocos 资源、原生配置和可见 UI 补丁 | 图片、动画、名称、按钮与本机屏幕尺寸是本地资源或布局，服务端无法更改已安装包。 |
| 邀请码页布局、复制、战绩页当日总场次与总分 | 客户端表单、系统剪贴板、局部统计标签 | 服务端负责提供真实数据和奖励；原厂没有新的标签布局或复制交互。 |

## 当前 R234 分数链路与保留项

当前发布的 Android APK 和默认 iOS IPA 都从原厂 R234 的同一 `project.jsc` 基线构建。它在房间信息解析时执行 `scoreRatio = score_ratio || 1`；麻将的玩家信息显示、每局结算数据对象和牌局总结束对象按该倍率显示分数。服务端在 `server/shared.js` 回传 `score_ratio=10`，自身用整数保存十分之一分。旧内置 iOS 资源的五处分数额外除法保留在 `tools/ios-sync-patches.js`，仅供 `--cocos-base ios` 的对照构建，**不要**应用于当前 R234 包，否则可能二次缩小显示分数。

俱乐部消息回包、机器人和托管虽已由服务端修复，不意味着 UI 与协议的补丁可一并移除。下一次审查其他客户端补丁时，应先用原厂 R234 资源还原具体牌局/页面，再分别验证 Android、iOS 的包内脚本与真机行为；没有复现或协议证明的项目保持原实现。
