# 服务端结构

`server/index.js` 只负责装配：加载环境变量、创建 GameApp / 存档队列 / 后台、HTTP 路由、WebSocket 接入和进程生命周期。

| 位置 | 内容 |
| --- | --- |
| `server/app.js` | `GameApp` 核心：连接、房间号、定时器、`onMessage` 入口；其余方法由 `game-app/*.js` mixin 挂上 |
| `server/game-app/common.js` | GameApp 各模块共用的依赖与常量 |
| `server/game-app/accounts.js` | 游客 / 微信 / token 登录、微信迁移、邀请码、实名、房卡余额 |
| `server/game-app/messages.js` | 公告、客服会话、运营消息、代理申请、俱乐部申请消息 |
| `server/game-app/bots.js` | 陪玩机器人、托管与记牌器白名单 |
| `server/game-app/clubs.js` | 俱乐部视图、方案牌桌、俱乐部战绩 |
| `server/game-app/persistence.js` | 运行快照 `dump` / `restore` |
| `server/game-app/handlers/*.js` | WebSocket 协议处理器，按协议号分文件：session / account / club / record / room |
| `server/game-app/handlers/dispatch.js` | 协议号 → 处理器表；未登录时只放行 `auth: false` 的处理器 |
| `server/http/*.js` | HTTP 工具、静态资源与 PWA、分享页、网页微信登录凭据 |
| `server/ws-guard.js` | WebSocket 令牌桶限流（`QJQP_WS_RATE` / `QJQP_WS_BURST`）、协议层心跳（`QJQP_WS_PING_MS`）、单帧上限（`QJQP_WS_MAX_PAYLOAD`，默认 256KB） |

## 新增协议

在 `game-app/handlers/` 对应文件里加一项 `{ order, protos: [id], handle(c, msg, proto, connId) { ... } }`。
`handle` 以 GameApp 实例为 `this` 调用；同一协议号有多项时按 `order` 从小到大执行，返回 `FALLTHROUGH` 才会继续下一项。
未在表中的协议由 `onMessage` 兜底：有 `res` 字段的回一个成功，否则忽略。

## 存档

`store.save` 为增量写：按主键比对上次写入的 JSON，只写变化的行；无法保持原有顺序或出现唯一约束冲突时，该表在同一事务内整表重写。
`synchronous=NORMAL`（WAL 模式下断电最多丢最近几次提交，不会损坏库）。`store.writeStats` 可查看累计写入行数。
