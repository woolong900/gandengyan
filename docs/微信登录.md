# 微信登录与分享配置

当前 Android 客户端已经包含微信登录原生代码。重新签名后，必须在微信开放平台登记新签名，并使用自己移动应用的 AppID。

微信开放平台移动应用填写：

- Android 包名：`com.haoke.gandengyan`
- Android 应用签名：`5a5996d5a09e4e862feaed2b1fe779f3`
- 签名算法：APK 签名证书的 MD5，小写且不带冒号

开放平台审核通过并取得 AppID、AppSecret 后，在项目根目录 `.dev.vars` 增加：

```dotenv
QJQP_WECHAT_APPID=wx替换为开放平台AppID
QJQP_WECHAT_APPSECRET=替换为开放平台AppSecret
```

`AppSecret` 只由服务端读取，不会写入 APK。构建脚本只把 `QJQP_WECHAT_APPID` 写入 AndroidManifest。运行：

```bash
npm run apk:install
```

命令会生成带时间戳的 APK、用 `~/.android-qjqp.keystore` 中的 `gandengyan` 私钥别名签名，并安装到所有在线 ADB 设备。这个签名库必须长期保留；更换签名后需要重新修改微信开放平台登记的应用签名。

服务端收到客户端的一次性授权码后，会通过微信接口换取用户身份，并以 `openid`/`unionid` 复用已有玩家账号。微信 access token 和 AppSecret 都不会返回客户端或写入存档。

## iOS

iOS 移动应用还需要一个稳定的 HTTPS Universal Link，例如：

```dotenv
QJQP_WECHAT_APPLINK=https://game.example.com/wechat/
QJQP_PUBLIC_BASE_URL=https://game.example.com
QJQP_APPLE_TEAM_ID=4CSMM3394C
```

在微信开放平台的 iOS 应用配置中填写：

- Bundle ID：`com.haoke.gandengyan`
- Universal Link：与 `QJQP_WECHAT_APPLINK` 完全一致，包括末尾 `/`

服务端会直接提供两个 Apple 要求的 AASA 地址：

- `https://game.example.com/apple-app-site-association`
- `https://game.example.com/.well-known/apple-app-site-association`

两个地址都必须从公网以 `application/json` 直接返回，不能重定向。Apple App ID 和用来签名的 provisioning profile 必须启用 **Associated Domains**，应用权限中对应的值为：

```text
applinks:game.example.com
```

当前使用的免费 Personal Team 描述文件不包含 Associated Domains，因此只能安装和测试游戏主体，不能完成微信 iOS 的 Universal Link 校验。需要先加入付费 Apple Developer Program，再为正式 App ID 开启 Associated Domains 并重新生成描述文件。

当 `QJQP_WECHAT_APPLINK` 已配置时，`tools/build-ios-ipa.js` 会检查描述文件是否包含 Associated Domains，并把精确域名写入最终签名权限。如果描述文件没有该权限，构建会直接拒绝，避免生成一个能安装但微信永远无法回调的 IPA。

`/download/ylhy-activity` 现在是项目自己的微信分享落地页，邀请链接会显示房间号。`/v1/forwardconfig` 会把分享域名指向 `QJQP_PUBLIC_BASE_URL`，避免再使用原厂域名。
